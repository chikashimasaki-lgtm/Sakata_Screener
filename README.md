# 酒田五法 シグナル・スクリーナー

株価API（Yahoo Finance 日足）から多銘柄をスキャンし、**酒田五法のシグナルが点灯した銘柄を一覧化**する
GAS ＋ GitHub Pages アプリ。**投資助言ではなく、シグナル抽出の補助ツール。**

## 検出パターン

| パターン | 内容 | 方向 |
|---|---|---|
| 赤三兵 | 陽線3本の切り上げ | 買い |
| 三羽烏(黒三兵) | 陰線3本の切り下げ | 売り |
| 三空踏み上げ | 上の窓が3連続（買われ過ぎ） | 売り |
| 三空叩き込み | 下の窓が3連続（売られ過ぎ） | 買い |
| 上げ三法 | 長陽→値幅内の調整→上抜け陽線 | 買い |
| 下げ三法 | 長陰→値幅内の調整→下抜け陰線 | 売り |

| 三山(三尊天井) | 3つの山（中央が最高）でネックライン割れ | 売り |
| 三川(逆三尊) | 3つの谷（中央が最安）でネックライン上抜け | 買い |

| 明けの明星 | 長大陰線→窓開けの星→陽線でC実体中心を回復 | 買い |
| 宵の明星 | 長大陽線→窓開けの星→陰線でC実体中心を割る | 売り |
| 捨て子線(明け/宵) | 中央が同事線で両側に窓が開く強い反転（明け=買い/宵=売り） | 買い/売り |

### 現代版フィルター（RSI補強・close値のみ）

形状シグナルにRSI(14)の裏付けを加点し、だましを抑える。

- **三空踏み上げ** … RSI80超なら `RSI過熱(80超)` を加点（反落を補強）
- **三空叩き込み** … RSI20割れなら `RSI底値(20割れ)` を加点（反発を補強）
- **三山/三川** … 天底でRSIが逆行（ダイバージェンス）なら `RSIダイバージェンス` を加点

### 価格データの扱い

- **分割・配当調整済み価格**を使用（Yahoo の `adjclose` で OHLC を調整）。未調整だと分割日に巨大な窓が開き、三空叩き込み・明けの明星が誤点灯する。
- **流動性フィルター**：直近20日の売買代金（終値×出来高）中央値が5,000万円未満の銘柄は走査対象外。薄商い銘柄は実際には約定していない「気配だけの窓」を拾うため。
- **欠損日のまたぎ**：データが飛んでいる区間では窓（三空・明星・二羽烏）の判定を行わない。実在しないギャップを窓と誤認しないため。

※ ボリンジャーのバンドウォークは未対応。

## セットアップ

1. Apps Script プロジェクトを作成し `src/` を push（clasp）
2. スプレッドシートを再読み込み → メニュー「酒田五法」→ セットアップ
3. 「銘柄」シートにコード(4桁)を入力
   - または「プライム銘柄を取得（J-Quants）」で自動取得（要 `JQUANTS_API_KEY` スクリプトプロパティ）
4. 「シグナル走査/続行」を実行（銘柄数が多いと時間分割で自動再開）

**UI はスプレッドシートのみ**。以前あった GitHub Pages の公開ページ（`index.html`）と JSON 出力機能は廃止済み。

### スクリプトプロパティ

いずれも任意。未設定でも該当機能を飛ばして動作する。

| キー | 用途 |
|---|---|
| `JQUANTS_API_KEY` | プライム銘柄一覧・海外投資家動向・決算データの取得（J-Quants） |
| `EDINETDB_API_KEY` | 決算カレンダー（数日先までの発表予定日）の取得（edinetdb.jp） |
| `ASSET_STATUS_SS_ID` | 保有銘柄ハイライトの参照元スプレッドシートID（Asset_Status） |
| `TRADINGVIEW_LAYOUT_ID` | コード列のリンク先に使う TradingView のチャートレイアウトID |

### 相場マクロの手入力

「相場マクロ」シートの B列が値、C列が最終更新日。C列が10日以上前または空欄だと「更新が古い」と警告する。

東証の売残・信用倍率は JPX の信用取引現在高ファイル（`mtseisan*.xls`）から自動取込するが、**JPX はボットからの直接ダウンロードを拒否する**ため、ファイルの入手だけは手作業でブラウザからDLし、Googleドライブに置く必要がある。

売残・信用倍率が未入力のときは地合いを NEUTRAL として扱う（未入力を「売残0＝枯渇」と読んで売りシグナルを増幅しないため）。

### 決算カレンダー

メニュー「決算カレンダーを更新」（`EDINETDB_API_KEY` 要設定）で「銘柄」シート対象コードの決算発表予定日を「決算カレンダー」シートへ出力する。J-Quants の決算発表予定（`fins/announcement`）は「翌営業日分のみ」しか返せない仕様のため、数日〜2週間先までを見たい用途には edinetdb.jp の `/v1/calendar`（日付範囲指定可）を使っている。「確度」列の「予測」は edinetdb.jp 側が開示履歴から推定した未確定の発表予定日であることを示す（公式発表ではない）。キー未設定時は他の機能に影響せず、この更新だけ静かにスキップされる。

## テスト

```
npm test        # または node tests/verify.js
```

GAS API をモックした上で `src/Code.js` と `src/MarketMacro.js` をそのまま読み込み、純ロジックを実際に動かす（依存パッケージなし・110項目）。RSI と MACD は教科書実装との一致を確認し、パターン検出・分割調整・信用残の読み取り・急落7条件は「間違った結果が正しそうな見た目で出る」ケースを重点的に見ている。ロジックを変えたら `clasp push` の前にこれを通すこと。

## 強さ★の意味

各シグナルの静的な重み（1〜3）を合計し、信用需給の地合い係数を掛けたスコアで、絶対しきい値により★を付ける（★★★=5以上、★★=3以上）。

**★は「形状シグナルの強さ」であって期待収益ではない。**

「パターン成績」シートの集計は**参考値で、順位付けには使っていない**。生の騰落率のみでベンチマークを控除しておらず、サンプル数も勝率60%と50%を統計的に区別できる水準に達していないため。

## 注意

- データは Yahoo Finance 日足（`.T` 東証）。シグナルはだましもあるため必ず自身で確認すること。
- 銘柄数が多い場合、走査は GAS の実行時間内で分割し 90 秒後に自動再開する。
- **損切り・利確・ポジションサイジング・銘柄分散は本ツールの対象外**。シグナル抽出のみを行う。
