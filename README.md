# 短期売買支援（ダウ理論×フィボナッチの買い推奨）

株価API（Yahoo Finance 日足）でプライム全銘柄を毎営業日の引け後に走査し、**ダウ理論の上昇トレンドの押し目が
フィボナッチの押し幅で止まって反転した銘柄**を、1日最大5件の「買い推奨」として出す GAS アプリ。
UI は Google スプレッドシート「売買プラン」1枚（買い推奨＋保有株）。**投資助言ではなく、抽出の補助ツール。**

> 旧名「酒田五法 シグナル・スクリーナー」。2026-10-04 に判定を全面的に作り直した（下の「作り直した理由」）。
> リポジトリ名・フォルダ名（`Sakata_Screener`）は CI・改善提案ルーチンが参照しているため据え置き。

## 買い推奨の条件（`src/DowFib.js`）

| # | 条件 | 中身 |
|---|---|---|
| ① | 主要トレンドが上昇（ダウ理論） | 左右10本で確定する大きな山谷で **安値切り上げ** かつ直近の上昇で **高値更新** |
| ② | 押しの深さ（フィボナッチ） | 直近の上昇幅（押し安値L→高値H）に対する押しが **23.6%〜78.6%**。ダウの「調整は上昇幅の1/3〜2/3」とほぼ同じ帯 |
| ③ | 押しの終わり | 押しの途中にできた小さな戻り高値（左右2本の山）を、当日の終値で **初めて** 上抜けた |
| ④ | 流動性 | 直近20日の売買代金中央値 5,000万円以上 |

- **確度A** … さらに「押し38.2%以上」かつ「当日出来高が20日平均の1.5倍以上」（ダウ理論「出来高はトレンドを確認する」）
- 並び … 確度A→出来高倍率の大きい順に最大5件。保有中の銘柄は推奨から外し、保有行のメモに「買い増し候補」と書く
- 注文 … 翌営業日の**寄付で買い**、利確・損切りをOCOで置く。寄付が損切り以下／利確以上なら見送り
- **損切り** = 押し目の安値 − ATR14×0.1（割れたら安値切り上げが崩れる＝ダウ理論の否定）
- **利確** = L + 上昇幅 × **1.618**（フィボナッチ・エクステンション）。どちらにも届かなければ **40営業日** で手仕舞い
- 株数 = 損切りまでの下落×株数が許容損失（既定3万円）に収まる最大値（100株単位・建玉上限100万円）

スイングは右側の本数が揃ってから確定し、確定後は動かない。H/L 交互への圧縮も判定日で切ってから行うので、
**未来の足を見ない**（テストで「未来の足を足しても過去の判定が変わらない」ことを確認している）。

## 検証結果（`tools/backtest_dowfib.js`）

過去10年（2016-10〜2026-10）・プライム約1,200銘柄の日足で、本番と同じ `src/DowFib.js` を動かした結果。
**基準（ベンチ）は「同じ日に全銘柄を買って20営業日持った平均」**。相場全体の上げ下げを差し引くため。
閾値は前半（〜2021年）で決め、後半（2022年〜）は答え合わせに使った。

| | 前半 2016-2021 | 後半 2022-2026 | 1日の件数 |
|---|---|---|---|
| ベンチ（全銘柄20日保有） | +0.54% | +1.26% | — |
| **確度A**（20日保有・ベンチ差） | **+0.37%** | **+1.82%** | 0.4〜0.5件 |
| 確度A（損切り・利確つき 1回平均／勝率／PF） | +0.76%／44%／1.17 | +2.61%／48%／1.67 | |
| 確度B（20日保有・ベンチ差） | −0.68% | +0.53% | 1.7〜2.0件 |
| 上位5件すべて（20日保有・ベンチ差） | −0.47% | +0.79% | 2.1〜2.5件 |
| 旧・酒田五法 ★3買い（20日保有・ベンチ差） | −0.44% | −0.53% | 10〜15件 |

- 確度Aは10年中7年でベンチを上回った。**確度Bはベンチ並み**で、5件に満たない日の穴埋めと考える。
- 1日の件数は平均2〜3件（上限5件）。「直近2〜3日以内の上抜け」まで広げても件数は1〜2割しか増えず、前半の成績が落ちたので採用していない。
- 日経平均のトレンドで絞る・相対力・押しの日数などは、期間で効き方が反転したため使っていない。
- 現在の上場銘柄だけで検証しているので（生存バイアス）、ベンチもろとも甘めに出る。比較はベンチ差で見ること。

再現:

```
# Yahoo の range=10y 日足を <コード>.T.json として BARS_DIR に置く（_N225.json も）
BARS_DIR=… node tools/backtest_dowfib.js --old --split 2022-01-01
DF_A_VOL_RATIO=2 BARS_DIR=… node tools/backtest_dowfib.js    # DF の閾値は環境変数で上書きして比較できる
```

### 作り直した理由

旧・酒田五法の★3買いは、10年のどちらの期間でも「全銘柄を無差別に買う」より約0.5%/20日劣後していた
（ローソク足の形そのものに予測力がほぼ無い）。ダウ理論の日足の細かい波（左右3本）で押し目を測る素案も
前半期間でベンチに負けたため、ダウ本来の「主要トレンド」と「二次的調整」の尺度（左右10本）に合わせ、
出来高の確認を加えた現在の形にした。

## 画面と通知

- **売買プラン**（一番左のタブ）… 区分「買い推奨A／B」「保有」。右上に「更新時刻｜買い推奨N件（確度A n件）｜保有N件」。
  見出し行と区分・コード・銘柄名の3列を固定。コードは TradingView の日足へのリンク。メモには決算予定と Bloomberg の関連記事（あれば）を添える。
- 通知メール（該当がある日だけ）… `短期売買支援_買い推奨_N件（確度A n件）` / `短期売買支援_保有株トレンド崩れ_N件`。
  シートと同じ数字を載せ、送信後に `利益累計` ラベルを付けてアーカイブ。
- 「シグナル」（走査の作業場所）・「パターン成績」（旧集計）・「急落サイン」（統合済み）は走査後に自動で**非表示**にする（削除はしない）。

## 投資デイリー分析（MarketBriefing）との連動

走査完了時に「投資デイリー分析」スプレッドシートへ書き込む（このシートは本スクリプトだけが書く）。

- `日本株_買い推奨` … 当日の買い推奨（成立分）
- `ニュース_Bloomberg` … Gmail に届く Bloomberg ニュースレター最新号の5本＋その他の注目ニュース（毎朝7時半にも更新）

書き込み先はドライブ上の「投資デイリー分析」をファイル名で探し、見つけたIDを `MARKET_BRIEFING_SS_ID` に保存する
（名前が重複するときは手で設定）。Bloomberg のメールは MailCleanup がすぐゴミ箱へ移すため `in:anywhere` で読む。
Gmail の権限を持つのはこちらのスクリプトなので、MarketBriefing 側には足していない（足すと全トリガーの再承認が要る）。

## セットアップ

1. `clasp push`（`rootDir: src`）
2. スプレッドシートを再読み込み → メニュー「短期売買支援」→ 設定とメンテナンス → セットアップ
3. 「銘柄」シートにコード(4桁)を入力（または「プライム銘柄を取得（J-Quants）」、要 `JQUANTS_API_KEY`）
4. 「自動実行を設定」… Bloomberg 7時半／相場マクロ・決算カレンダー 17時／走査 平日18時

### スクリプトプロパティ

いずれも任意。未設定でも該当機能を飛ばして動作する。

| キー | 用途 |
|---|---|
| `JQUANTS_API_KEY` | プライム銘柄一覧・海外投資家動向・決算データの取得（J-Quants） |
| `EDINETDB_API_KEY` | 決算カレンダー（14日先までの発表予定日）の取得（edinetdb.jp） |
| `ASSET_STATUS_SS_ID` | 保有銘柄の参照元スプレッドシートID（Asset_Status） |
| `MARKET_BRIEFING_SS_ID` | 投資デイリー分析のスプレッドシートID（未設定ならファイル名で自動検出） |
| `TRADINGVIEW_LAYOUT_ID` | コード列のリンク先に使う TradingView のチャートレイアウトID |
| `SAKATA_RISK_BUDGET_YEN` | 1トレードの許容損失額（既定 30,000円） |
| `SAKATA_MAX_POSITION_YEN` | 1銘柄あたり建玉上限（既定 1,000,000円） |

## 保有株のプラン（`buildOrderPlan_`）

保有株は日足を取り直し、ダウ理論の押し安値から返済売の2値（利確・損切り）を出す。

- 損切り = 押し安値の1ティック下（近すぎるときは ATR14×0.5 まで広げる）。利確 = 現在値 + 損切り幅 × 2.0
- 高値・安値の切り上げが揃わなくなったら、メモに「トレンド崩れ」と出して橙でハイライト（損切り価格自体は動かさない）
- 数量・取得単価が読めなければ損切り額は空欄（0株0円と出さない）。算出できなければ「算出不可」と理由
- 利確・損切りが値幅制限の外なら警告（勝手に丸めない）。呼値は通常銘柄の刻みで丸める

## 相場マクロ・決算カレンダー（参考表示）

推奨の判定には使っていない（地合いで絞っても成績が変わらなかったため）。

- 「相場マクロ」… B列が値、C列が最終更新日（10日以上前・空欄は警告）。東証の売残・信用倍率は JPX の
  `mtseisan*.xls` を手でDLしてドライブに置くと自動取込（JPX はボットからのDLを拒否する）。
  信用倍率（日経レバ1570）は水準ではなく前回公表比の方向で判定（実測10倍前後で「1.0割れ」の前提が成立しないため）。
- 「決算カレンダー」… edinetdb.jp `/v1/calendar`（日付範囲指定可）。「予測」は開示履歴からの推定で公式発表ではない。

## テスト

```
npm test        # または node tests/verify.js
```

GAS API をモックした上で `src/` の主要ファイルをそのまま読み込み、純ロジックを実際に動かす（依存パッケージなし・336項目）。
買い推奨は「先読みしない」「押し78.6%超・高値未更新・前日上抜け済みは出さない」「確度A/Bの境目」「注文値の呼値丸めと株数」を、
Bloomberg は実物と同じ構造の本文で見出し・本文の分解と社名照合を確認している。ロジックを変えたら `clasp push` の前にこれを通し、
判定の閾値を変えたらバックテストも回し直すこと。

旧・酒田五法の判定（`detectSakata_` ほか）と `tools/calc_weights.js` は、旧ロジックとの比較のために残している（走査には使っていない）。

## 注意

- データは Yahoo Finance 日足（`.T` 東証、分割・配当調整済み）。銘柄数が多いと走査は6分制限内で分割し90秒後に自動再開する。
- ここに出る価格は「判定の前提が崩れる水準」であって、値上がりの保証ではない。**銘柄分散・総リスク量の管理は本ツールの対象外**。
