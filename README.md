# 酒田五法 シグナル・スクリーナー

株価API（Yahoo Finance 日足）から多銘柄をスキャンし、**酒田五法のシグナルが点灯した銘柄を一覧化**する
GAS ＋ GitHub Pages アプリ。**投資助言ではなく、シグナル抽出の補助ツール。**

## 検出パターン

| パターン | 内容 | 方向 |
|---|---|---|
| 赤三兵 | 陽線3本の切り上げ | 買い |
| 三羽烏(黒三兵) | 陰線3本の切り下げ | 売り |
| 三空踏み上げ | 上の窓が3連続（買われ過ぎ） | 売り |
| 三空叩き込み | 下の窓が3連続（売られ過ぎ） | 買い |
| 上げ三法 | 長陽→値幅内の調整→上抜け陽線 | 買い |
| 下げ三法 | 長陰→値幅内の調整→下抜け陰線 | 売り |

| 三山(三尊天井) | 3つの山（中央が最高）でネックライン割れ | 売り |
| 三川(逆三尊) | 3つの谷（中央が最安）でネックライン上抜け | 買い |

| 明けの明星 | 長大陰線→窓開けの星→陽線でC実体中心を回復 | 買い |
| 宵の明星 | 長大陽線→窓開けの星→陰線でC実体中心を割る | 売り |
| 捨て子線(明け/宵) | 中央が同事線で両側に窓が開く強い反転（明け=買い/宵=売り） | 買い/売り |

### 現代版フィルター（RSI補強・close値のみ）

形状シグナルにRSI(14)の裏付けを加点し、だましを抑える。

- **三空踏み上げ** … RSI80超なら `RSI過熱(80超)` を加点（反落を補強）
- **三空叩き込み** … RSI20割れなら `RSI底値(20割れ)` を加点（反発を補強）
- **三山/三川** … 天底でRSIが逆行（ダイバージェンス）なら `RSIダイバージェンス` を加点

### 価格データの扱い

- **分割・配当調整済み価格**を使用（Yahoo の `adjclose` で OHLC を調整）。未調整だと分割日に巨大な窓が開き、三空叩き込み・明けの明星が誤点灯する。
- **流動性フィルター**：直近20日の売買代金（終値×出来高）中央値が5,000万円未満の銘柄は走査対象外。薄商い銘柄は実際には約定していない「気配だけの窓」を拾うため。
- **欠損日のまたぎ**：データが飛んでいる区間では窓（三空・明星・二羽烏）の判定を行わない。実在しないギャップを窓と誤認しないため。

※ ボリンジャーのバンドウォークは未対応。

## セットアップ

1. Apps Script プロジェクトを作成し `src/` を push（clasp）
2. スプレッドシートを再読み込み → メニュー「酒田五法」→ セットアップ
3. 「銘柄」シートにコード(4桁)を入力
   - または「プライム銘柄を取得（J-Quants）」で自動取得（要 `JQUANTS_API_KEY` スクリプトプロパティ）
4. 「シグナル走査/続行」を実行（銘柄数が多いと時間分割で自動再開）
5. 走査完了時に「売買プラン」シートが自動生成される（★3買い＋保有株）

**UI はスプレッドシートのみ**。以前あった GitHub Pages の公開ページ（`index.html`）と JSON 出力機能は廃止済み。

### スクリプトプロパティ

いずれも任意。未設定でも該当機能を飛ばして動作する。

| キー | 用途 |
|---|---|
| `JQUANTS_API_KEY` | プライム銘柄一覧・海外投資家動向・決算データの取得（J-Quants） |
| `EDINETDB_API_KEY` | 決算カレンダー（数日先までの発表予定日）の取得（edinetdb.jp） |
| `ASSET_STATUS_SS_ID` | 保有銘柄ハイライトの参照元スプレッドシートID（Asset_Status） |
| `TRADINGVIEW_LAYOUT_ID` | コード列のリンク先に使う TradingView のチャートレイアウトID |
| `SAKATA_RISK_BUDGET_YEN` | 売買プランの1トレード許容損失額（既定 30,000円） |
| `SAKATA_MAX_POSITION_YEN` | 売買プランの1銘柄あたり建玉上限（既定 1,000,000円） |

### 相場マクロの手入力

「相場マクロ」シートの B列が値、C列が最終更新日。C列が10日以上前または空欄だと「更新が古い」と警告する。

東証の売残・信用倍率は JPX の信用取引現在高ファイル（`mtseisan*.xls`）から自動取込するが、**JPX はボットからの直接ダウンロードを拒否する**ため、ファイルの入手だけは手作業でブラウザからDLし、Googleドライブに置く必要がある。

売残・信用倍率が未入力のときは地合いを NEUTRAL として扱う（未入力を「売残0＝枯渇」と読んで売りシグナルを増幅しないため）。

### 決算カレンダー

メニュー「決算カレンダーを更新」（`EDINETDB_API_KEY` 要設定）で「銘柄」シート対象コードの決算発表予定日を「決算カレンダー」シートへ出力する。J-Quants の決算発表予定（`fins/announcement`）は「翌営業日分のみ」しか返せない仕様のため、数日〜2週間先までを見たい用途には edinetdb.jp の `/v1/calendar`（日付範囲指定可）を使っている。「確度」列の「予測」は edinetdb.jp 側が開示履歴から推定した未確定の発表予定日であることを示す（公式発表ではない）。キー未設定時は他の機能に影響せず、この更新だけ静かにスキップされる。

「シグナル」シートK列（決算発表）も同じデータを使う。`EDINETDB_API_KEY` 設定時は「2026-08-05(確定)」のように発表(予定)日＋確度を表示し、未設定/取得失敗時は従来どおり J-Quants ベースの「明日発表予定」フラグにフォールバックする。

## 売買プラン（ダウ理論ベース）

**今日さわる銘柄だけを1枚に並べたシート**。★★★かつ方向「買い」のシグナルと、いま保有している
全銘柄について、**買い・利確・損切りの3価格と株数**を計算して「売買プラン」シートへ出す。

| 区分 | 対象 | 出すもの |
|---|---|---|
| **★3買い** | これから建てる銘柄 | 買い・利確・損切りと、許容損失から逆算した株数 |
| **保有** | いま持っている全銘柄（シグナルの有無によらず） | 実際の建値・株数と、これから置くべき返済売の2値（利確・損切り） |

保有株はすでに建っているので買値と株数は逆算せず、リスクの起点は買値ではなく**現在値**にする
（これから失いうるのは現在値から損切りまでの下落分のため）。同じ銘柄が両方に該当したときは
「保有」1行にまとめ、買い増し候補であることをメモに残す。まずやることは新規建てではなく
返済売の置き直しなので、買いプランを併記するとどちらを実行すべきか迷うため。

価格の見出しに付く OCO1/OCO2 は SBI証券アプリの信用注文画面の欄名で、画面を見ながら転記できる。
メニュー「売買プランを作成/更新」で走査せずに引き直せる（許容損失額を変えたときや、
保有銘柄を入れ替えたとき）。★3買いの日次メールにも同じ数字が1行付く。

### 計算根拠

ダウ理論は上昇トレンドを「高値切り上げ・安値切り上げ」で定義し、トレンドは明確な転換シグナルが
出るまで継続するとみなす。裏を返せば **直近の押し安値を割った時点で上昇トレンドは否定された** ので、
そこが最も理屈の通った損切り位置になる。

| 項目 | 決め方 |
|---|---|
| **損切り**（OCO2） | 押し安値の1ティック下。ダウ理論の上昇トレンド否定水準 |
| **買い**（価格） | 上昇トレンド継続中なら現値の**指値**（押し目待ち）。まだ高値切り上げが確認できていなければ、直近の戻り高値を上抜けた**逆指値**（＝ダウ理論上の転換が確定する水準）。保有行は実際の建値 |
| **利確**（OCO1） | 基準価格 + 損切り幅 × 2.0。ダウ理論に利確の水準は無いので、損切り幅に対する固定比率で置く |
| **株数** | ★3買いは許容損失額（既定3万円）に収まる最大株数を100株単位で切り捨て。建玉上限（既定100万円）で頭打ち。保有行は実際の保有数 |
| **損切り額** | 損切り幅 × 株数の実額 |

スイングの確定には左右3本を要求するので、**確定したスイングは後から動かない**（リペイントしない）。

### 出さない・黙らせない

- **押し安値は「確定スイング安値以降の最安値」**を使う。確定スイング安値そのものだと、右側3本がまだ無く
  スイングと認定できない直近の切り下げを無視してしまい、明けの明星のような大底の転換で損切りが現値より
  上に来る。
- **損切りが近すぎるときは ATR14×0.5 まで広げる**。押し安値が現値のすぐ下にあると、理論どおりの位置は
  日中のノイズでほぼ確実に狩られる。
- **許容損失内で100株も建てられない銘柄は「見送り」**にして理由を書く。株数0の行をそのまま出すと、
  数字が埋まっているように見えて発注してしまう。保有株は「見送り」ではなく「算出不可」と書く
  （持っている以上、見送るという選択肢が無いため）。
- **保有株の数量が読めなければ損切り額は空欄**にする。0株として0円と出すと、リスクが無いように見える。
  数量・取得単価は Asset_Status の「保有株数」「取得単価」等の列から拾い、列名が違えば価格だけ出す。
- **利確・損切りが値幅制限の外なら警告する**（勝手に丸めない）。丸めるとダウ理論上の水準と違う数字になる。
  制限値幅は基準値段＝最終足の終値から算出（大引け後に翌営業日の注文を出す前提）。
- 呼値は**通常銘柄の刻み**で丸める。TOPIX100構成銘柄の刻みは全価格帯でその約数なので、
  構成銘柄リストを持たなくても板に乗る値段になる。

**この数字は「シグナルの前提が崩れる水準」であって、値上がりの保証ではない。**

## テスト

```
npm test        # または node tests/verify.js
```

GAS API をモックした上で `src/Code.js` と `src/MarketMacro.js` をそのまま読み込み、純ロジックを実際に動かす（依存パッケージなし・221項目）。RSI と MACD は教科書実装との一致を確認し、パターン検出・分割調整・信用残の読み取り・急落7条件・売買プランの価格算定は「間違った結果が正しそうな見た目で出る」ケースを重点的に見ている。制限値幅は実際の注文画面の表示値（基準値段1,595.5 → 1,195.5〜1,995.5）と突き合わせている。ロジックを変えたら `clasp push` の前にこれを通すこと。

## 強さ★の意味

各シグナルの静的な重み（1〜3）を合計し、信用需給の地合い係数を掛けたスコアで、絶対しきい値により★を付ける（★★★=5以上、★★=3以上）。

**★は「形状シグナルの強さ」であって期待収益ではない。**

「パターン成績」シートの集計は**参考値で、順位付けには使っていない**。生の騰落率のみでベンチマークを控除しておらず、サンプル数も勝率60%と50%を統計的に区別できる水準に達していないため。

## 注意

- データは Yahoo Finance 日足（`.T` 東証）。シグナルはだましもあるため必ず自身で確認すること。
- 銘柄数が多い場合、走査は GAS の実行時間内で分割し 90 秒後に自動再開する。
- 損切り・利確・株数は**★3買いと保有株について**「売買プラン」シートで算出する（上記）。
  **銘柄分散・総リスク量の管理は本ツールの対象外**。
